1. What StarkLLM is

StarkLLM is a private, local-first AI assistant designed for Windows. It provides a secure interface to chat with open-weight Large Language Models (LLMs) running directly on your machine. Through Retrieval-Augmented Generation (RAG), it allows you to upload documents (PDF, DOCX, TXT, MD, CSV, JSON, HTML), storing them in a local vector database to provide source-grounded answers to your questions.

2. Who it is for

StarkLLM is built for researchers, analysts, developers, and privacy-conscious professionals who need to interrogate sensitive documents without exposing them to third-party cloud providers. If you work under strict data governance policies or simply value data privacy, this tool is designed for you.

3. What it is not for

StarkLLM is not a cloud chatbot (like ChatGPT or Claude). It does not rely on remote server farms. It is also not a zero-configuration consumer app; the initial setup requires installing underlying dependencies like Docker and Ollama. If you want instant, low-effort AI and do not mind cloud data transmission, a cloud subscription will be easier and faster.

4. Required hardware

Hardware Guidance

StarkLLM is a local AI system. Inference speed and capability depend on your PC specifications. Dedicated GPUs provide significantly faster answer generation.

  • Basic / Laptop Tier: Modern CPU, 8 GB RAM. Recommended for lightweight 3B models (e.g. qwen2.5:3b). Usable for document summaries, but slower on large context.
  • Standard Tier (Recommended): Intel i7 / Ryzen 7, 16–32 GB RAM, NVIDIA RTX 3060 / 4060 (8GB+ VRAM). Offers fast, fluid inference for 7B models (e.g. qwen2.5:7b) and handles 14B models comfortably.
  • Power User Tier: Intel i9 / Ryzen 9, 32–64 GB RAM, NVIDIA RTX 3090 / 4090 (16–24GB VRAM). Enables running larger 14B–32B models with extensive context windows.
  • Storage: Fast NVMe or SATA SSD with at least 30–50GB of free space for Docker containers and local model weights.

5. Required software

Because StarkLLM runs entirely locally, it relies on standard containerization and inference engines:

  • Windows 10 or 11 with WSL2 (Windows Subsystem for Linux) enabled.
  • Docker Desktop: Used to orchestrate the vector database, backend API, and frontend UI.
  • Ollama: The inference engine responsible for running LLM models locally on your host machine.

6. Recommended models

Recommended Model Configuration

StarkLLM recommends qwen2.5:7b for text generation and nomic-embed-text for document vector embedding.

  • Balanced Default (qwen2.5:7b): High-accuracy model providing strong reasoning and document comprehension. Requires ~8GB–16GB RAM/VRAM.
  • Lightweight Option (qwen2.5:3b): Fast, low-footprint model suitable for 8 GB RAM systems or CPU-only setups.
  • High-Capability Option (qwen2.5:14b): 14B models providing superior analytical depth on 16GB+ VRAM/RAM setups.
  • Default Embedding Model (nomic-embed-text): Fast, high-accuracy embedding model optimized for local RAG retrieval.

7. Installation overview

Installation involves preparing your host machine and then running the launcher:

  1. Ensure Docker Desktop is installed and running.
  2. Install Ollama from ollama.com.
  3. Pull recommended models in your terminal:
    ollama pull qwen2.5:7b
    ollama pull nomic-embed-text
  4. Extract the StarkLLM release package completely to a directory (e.g. C:\StarkLLM\).

8. Launching StarkLLM

Navigate to the extracted StarkLLM folder. Choose from the available launcher options:

First Launch Note: First launch can take several minutes while Docker images initialize. Once containers are running, the backend initializes in 1–2 minutes. The setup wizard opens automatically at http://localhost:5173 when ready.

⚠️ Windows SmartScreen / Execution Notice

Files extracted from downloaded zip archives carry a Mark of the Web (MOTW) attribute. When running start.exe, click More info → Run anyway, or run unblock.ps1 in PowerShell to clear the attribute locally.

Option 1 — Launch start.exe (Recommended)

StarkLLM includes a standalone start.exe launcher that automatically checks Docker Desktop status, checks Ollama availability, starts containers, and opens your browser to http://localhost:5173.

  1. Open the extracted folder in File Explorer.
  2. Click the address bar, type cmd (or powershell), and press Enter.
  3. Execute the launcher:
    • In Command Prompt (cmd): start.exe
    • In PowerShell: .\start.exe

Option 2 — Launch start.cmd (Terminal Fallback)

To launch via script in the terminal:

  1. In Command Prompt: start.cmd
  2. In PowerShell: .\start.cmd

Option 3 — Direct Docker Compose (Last Resort)

Run standard Docker compose directly from the terminal:

docker compose up --build -d

Option 4 — Run unblock.ps1 (If Execution Blocked)

If execution policies prevent script execution, open PowerShell in the extracted folder and run:

powershell -ExecutionPolicy Bypass -File unblock.ps1

After running unblock.ps1, run start.exe or start.cmd (or start.bat).

9. First-week usage path

To get the most out of StarkLLM, we recommend this progression during your first week:

  1. Day 1: Start small. Create a single workspace, upload 2-3 standard documents (like research papers or manuals), and practice asking questions. Observe how the citations work.
  2. Day 2: Experiment with model switching. Download a different model via Ollama (e.g., try qwen2.5:3b vs qwen2.5:7b or llama3.2) and compare how they answer the same document questions.
  3. Day 3: Upload a complex multi-page report. Notice how semantic chunking breaks it down into logical blocks.
  4. Day 4: Organize. Create distinct workspaces for different projects (e.g., "Finances", "Codebase", "Legal").
  5. Day 5+: Set up your Global Knowledge Base. Point StarkLLM to your permanent notes folder so you can query it across all chat sessions.

10. Creating a workspace

Workspaces isolate your data. In the left sidebar, click "New Workspace" to create a fresh context. For example, you might create a "Legal Review" workspace and a separate "Market Research" workspace. Documents and chats in one workspace cannot cross-contaminate another.

11. Uploading documents & Best Practices

Inside a workspace, click the "Upload Document" button or drag-and-drop supported files (PDF, DOCX, TXT, MD, CSV, JSON, HTML) into the designated area. StarkLLM processes the document in the background—extracting text, generating semantic chunks, and embedding vectors into local ChromaDB.

RAG Best Practices

For high quality answers, ensure your documents contain clean text. Ask specific, targeted questions rather than vague prompts to help the retrieval engine locate the most relevant sections.

12. Using chat with documents

Once a document is processed, you can ask questions in the chat interface. StarkLLM performs hybrid search to find the most relevant chunks from your uploaded documents, feeds those chunks to your local LLM, and generates an answer with verifiable citations.

13. Using Knowledge Base & Best Practices

The Knowledge Base feature allows you to map a local folder on your Windows host. StarkLLM copies supported files into the container and indexes them into a global vector collection. Unlike workspace-specific documents, the Knowledge Base acts as a global reference library that you can query from any chat session. The system polls the mapped folder approximately every minute and re-indexes new or modified files automatically.

Knowledge Base Guidance

Structure your local folder logically with text-heavy documents (Markdown, TXT, clean PDFs). Avoid pointing the Knowledge Base to an entire root drive containing thousands of binary system files.

14. Workspace vs Knowledge Base

StarkLLM offers two ways to contextualize the AI. Understanding the difference is critical to organizing your intelligence:

Workspace Documents

  • Tied strictly to one single workspace.
  • Keeps work isolated to prevent context contamination.
  • Best for temporary or project-specific document sets.
Example: Contracts for one specific legal review.

Knowledge Base

  • A persistent, global intelligence layer.
  • Available across all chats and workspaces simultaneously.
  • Best for permanent reference material and personal archives.
Example: Research archive or engineering documentation.

15. Switching models

If you have downloaded multiple models via Ollama (e.g., qwen2.5:7b, llama3.2, or mistral), you can switch between them using the dropdown menu in the StarkLLM chat interface. Changing models retains chat history while using the selected model for new replies.

16. Voice features

StarkLLM supports local Speech-to-Text (STT) for dictating messages and Text-to-Speech (TTS) for reading answers aloud. Ensure browser microphone permissions are enabled. Voice processing is handled locally without sending audio to external clouds.

17. Troubleshooting

  • "Cannot connect to Ollama": Ensure Ollama is running in your Windows system tray. Ollama runs natively on the host, and the Docker container communicates via host.docker.internal:11434. Verify you pulled the required model (ollama pull qwen2.5:7b).
  • Docker fails to start: Ensure Docker Desktop is running with WSL2 integration. If containers fail, try running docker compose down followed by docker compose up --build -d.
  • Slow responses: Ensure Ollama is utilizing your dedicated NVIDIA GPU rather than defaulting to CPU inference.

18. Limitations

  • Initial setup requires installing Docker Desktop and Ollama.
  • Response speed and throughput depend on your local hardware.
  • Document retrieval quality depends on the formatting and clarity of the input text.
  • StarkLLM is provided "as is" as an open-source Research Beta under Apache 2.0.

19. Frequently Asked Questions

1. Does my data leave my computer?

No. StarkLLM is designed to keep data strictly on your machine. Documents are stored in local ChromaDB containers and inference runs via Ollama on your PC.

2. Is StarkLLM free and open source?

Yes. StarkLLM is free and open source under the Apache 2.0 license. The source code is available on GitHub.

3. Where can I inspect or contribute to the source code?

Visit github.com/homomorphicprivacy/StarkLLM to review source code, inspect launchers, and open issues.
