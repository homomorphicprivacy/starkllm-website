1. What StarkLLM is

StarkLLM is a private, local-first AI assistant designed for Windows. It provides a secure interface to chat with open-weight Large Language Models (LLMs) running directly on your machine. Through Retrieval-Augmented Generation (RAG), it allows you to upload PDFs and text documents, storing them in a local vector database to provide source-grounded answers to your questions.

2. Who it is for

StarkLLM is built for researchers, analysts, developers, and privacy-conscious professionals who need to interrogate sensitive documents without exposing them to third-party cloud providers. If you work under strict data governance policies or simply value strong data privacy, this tool is designed for you.

3. What it is not for

StarkLLM is not a cloud chatbot (like ChatGPT or Claude). It does not rely on massive server farms. It is also not a zero-configuration consumer app; the initial setup requires installing underlying technical dependencies like Docker and Ollama. If you want instant, low-effort AI and do not care about data privacy, a cloud subscription will be easier and faster.

4. Required hardware (Crucial)

Hardware Reality

StarkLLM is a local AI system. If you do not have a sufficiently strong PC, your experience will be poor. Weak CPUs will result in slow answers. Low RAM will cause model load failures or system crashing. Without a capable local setup, StarkLLM cannot deliver its full value.

  • Minimum Tier (Acceptable but slow): Intel i5 / Ryzen 5 (8th/3000 series+), 16 GB RAM. Inference will run on CPU and be quite slow. You will be restricted to 8B models.
  • Good Tier (Recommended): Intel i7 / Ryzen 7, 32 GB RAM, NVIDIA RTX 3060 / 4060 (8GB+ VRAM). Offers fast, fluid inference for 8B models and can handle 14B models comfortably.
  • Excellent Tier (Power User): Intel i9 / Ryzen 9, 64 GB RAM, NVIDIA RTX 3090 / 4090 (24GB VRAM). Required for running exceptionally intelligent 32B+ models at high speeds with massive context windows.
  • Storage: Fast NVMe SSD with at least 50GB of free space for Docker images, vector databases, and LLM weights. Mechanical hard drives will cause severe performance degradation during document embedding.

5. Required software

Because StarkLLM runs entirely locally, it relies on standard containerization and inference engines.

  • Windows 10 or 11 with WSL2 (Windows Subsystem for Linux) enabled.
  • Docker Desktop: Used to orchestrate the vector database, backend API, and frontend UI.
  • Ollama: The inference engine responsible for actually running the LLM models locally.

6. Recommended models

Model Intelligence

The quality of answers depends heavily on the chosen local model. Small, weak models will feel "dumb". Stronger models perform better but demand more hardware.

  • Light Models (e.g., 8B - 14B): Fast and highly capable for document RAG. Requires ~6-12GB of RAM/VRAM to run smoothly. Ideal for the "Minimum" or "Good" hardware tier.
  • Default Text Model (qwen3.8:27b): Exceptional intelligence for multilingual document analysis. Requires ~16-24GB of RAM/VRAM. Highly recommended only if you have an "Excellent" tier hardware setup (RTX 3090/4090 or 32GB+ system RAM).
  • Default Embedding Model (qwen3-embedding:0.6b): Extremely fast, highly efficient 1024-dimension multilingual embedding model. Runs easily on all hardware tiers alongside your text model.

7. Installation overview

Installation involves preparing your host machine and then running the provided scripts.

  1. Install WSL2 (`wsl --install` in PowerShell).
  2. Install Docker Desktop and ensure WSL2 integration is enabled in its settings.
  3. Install Ollama for Windows and download your preferred model (e.g., `ollama pull qwen3.8:27b`).
  4. Extract the StarkLLM release package to a directory of your choice.

8. Launching StarkLLM

Navigate to the extracted StarkLLM folder. There are four ways to start the platform depending on whether Windows allows the script to run.

⚠️ Windows May Block start.bat

Because start.bat was downloaded from the internet, Windows Smart App Control or SmartScreen may flag it as potentially unsafe. This does not indicate malware. It is a standard Windows behaviour applied to internet-sourced scripts. StarkLLM is fully open-source — you are welcome to inspect the file before running it.

Option A — start.bat Control Panel (Easiest)

If Windows permits it, double-click start.bat. A simple text menu appears:

  • Press 1 — Start StarkLLM (runs docker compose up --build -d and opens your browser)
  • Press 2 — Stop StarkLLM (docker compose down)
  • Press 3 — Exit the control panel without changing anything

The app runs at http://localhost:5173. The first launch takes several minutes while Docker downloads and builds images. Subsequent starts are fast.

Option B — Unblock the File

If Windows blocks the script: right-click start.bat → Properties → check Unblock at the bottom → Apply → OK. Then run it again.

Option C — Run from a Terminal

Open a terminal (cmd or PowerShell) inside the project folder and run:

.\start.bat

Running from a terminal often bypasses SmartScreen without needing to unblock the file.

Option D — Manual Docker Commands

If start.bat remains inaccessible, control StarkLLM directly:

  • Start: docker compose up --build -d — then open http://localhost:5173
  • Stop: docker compose down

These commands are identical to what start.bat runs internally. There is no functional difference.

8. First-week usage path

To get the most out of StarkLLM, we recommend this progression during your first week:

  1. Day 1: Start small. Create a single workspace, upload 2-3 standard PDFs (like research papers or manuals), and practice asking questions. Observe how the citations work.
  2. Day 2: Experiment with model switching. Download a different model via Ollama (e.g., if you started with Llama 3, try Mistral) and compare how they answer the exact same document questions.
  3. Day 3: Push the limits. Upload a complex, scanned PDF or a massive 500-page report. Notice how semantic chunking breaks it down.
  4. Day 4: Organize. Create distinct workspaces for different areas of your life (e.g., "Finances", "Coding Projects", "Legal").
  5. Day 5+: Set up your Global Knowledge Base. Point StarkLLM to your permanent notes folder so you never have to re-upload them again.

Workspace vs Knowledge Base

StarkLLM offers two ways to contextualize the AI. Understanding the difference is critical to organizing your intelligence.

Workspace Documents

  • Tied strictly to one single workspace.
  • Useful when work must stay isolated to prevent context contamination.
  • Best for temporary or highly specific document sets.
Example:
A folder of contracts for one specific legal case.

Knowledge Base

  • A persistent, global intelligence layer.
  • Useful across all chats and ongoing workspaces simultaneously.
  • Best for long-term reference material and personal archives.
Example:
Your ongoing, permanent research library or company SOPs.

9. Creating a workspace

Workspaces isolate your data. In the left sidebar, click "New Workspace" to create a fresh context. For example, you might create a "Legal Review" workspace and a separate "Market Research" workspace. Documents and chats in one workspace cannot cross-contaminate another.

10. Uploading documents & Best Practices

Inside a workspace, click the "Upload Document" button or drag-and-drop PDFs/TXT files into the designated area. StarkLLM will process the document in the background—extracting the text, breaking it into semantic chunks, and embedding it into the local ChromaDB vector store. Note: Scanned PDFs without embedded text may require external OCR first.

RAG Best Practices

For the highest quality answers, ensure your documents are clean. Remove massive tables of raw numbers (which LLMs struggle to read natively) and ensure scanned documents are properly OCR'd. Ask specific, targeted questions rather than vague prompts like "summarize this".

11. Using chat with documents

Once a document is processed, you can ask questions in the chat interface. StarkLLM will perform a hybrid search to find the most relevant chunks of text from your uploaded documents, provide those chunks to the local LLM, and generate an answer. Citations will be provided, allowing you to trace answers back to the original document context.

12. Using Knowledge Base & Best Practices

The Knowledge Base feature allows you to specify a local folder on your Windows host. StarkLLM mounts this folder and indexes all supported files within it. Unlike workspace-specific documents, the Knowledge Base acts as a global reference library that you can query from any chat session.

Knowledge Base Best Practices

Structure your local folder logically. Only include text-heavy, informational documents (Markdown, TXT, clean PDFs). Do not point the Knowledge Base to your entire `C:\` drive or a folder containing thousands of images, binaries, or zip files, as this will crash the embedding process and pollute your vector space.

13. Switching models

If you have downloaded multiple models via Ollama (e.g., `qwen3.8:27b` and `mistral`), you can switch between them using the dropdown menu in the StarkLLM chat interface. Note that changing models mid-conversation will not lose chat history, but the tone and intelligence of the new model will apply to subsequent messages.

14. Voice features

StarkLLM supports local Speech-to-Text (STT) for dictating messages and Text-to-Speech (TTS) for reading answers aloud. Ensure your microphone permissions are granted in the browser. Voice processing happens entirely on your machine, preserving the privacy of your spoken words.

15. Troubleshooting

  • "Cannot connect to Ollama": Ensure the Ollama app is running in your system tray. Check that the `OLLAMA_HOST` variable in the StarkLLM settings matches your setup.
  • Docker fails to start: Ensure Docker Desktop is running. If containers fail, try running `docker-compose down` followed by `docker-compose up -d`.
  • Very slow responses: Your machine may be relying on CPU inference. Ensure you have an NVIDIA GPU and that Ollama is correctly detecting it.

16. Limitations

Be aware of the following technical realities:

  • The first setup is more technical than standard SaaS tools.
  • Speed depends entirely on your local hardware.
  • Document retrieval quality depends on the clarity of the original text.
  • StarkLLM is provided "as is" as a Research Beta, without commercial warranty.

Frequently Asked Questions

1. Does my data leave my computer?

StarkLLM is designed to keep your data on your machine. Documents are stored in a local ChromaDB container. AI inference runs via Ollama on your host machine. During normal local operation, no data is intended to be transmitted externally.

2. Is StarkLLM free?

Yes. It is free and open-source. There are no subscriptions or premium tiers. It is provided "as is" with no liability.

3. Why can answers be slow?

Speed depends on your hardware. If you do not have a dedicated GPU, Ollama defaults to CPU inference, which is significantly slower. A dedicated NVIDIA GPU (8GB+ VRAM) can significantly improve generation speed.

4. Why does Windows block start.bat?

Windows SmartScreen flags scripts downloaded from the internet. It does not mean the file is malware. You can unblock it via file Properties, or bypass SmartScreen by running .\start.bat directly from a terminal.

5. What hardware do I need?

At minimum: 16 GB RAM and an NVIDIA GPU with 8GB VRAM for 8-Billion parameter models. For demanding models (14B-32B), 24GB VRAM or 64GB system RAM is recommended.

6. What is the difference between normal chat and document chat?

Normal chat relies solely on the LLM's pre-trained knowledge. Document chat uses RAG: it searches your uploaded PDFs first, feeds relevant chunks to the LLM, and provides answers with specific citations to your documents.

7. What is the difference between Workspace Documents and Knowledge Base?

Workspace Documents are temporary and isolated to a specific project. The Knowledge Base is a persistent, global folder on your machine that can be referenced from any chat.

8. What if the UI opens but chat does not work?

Ensure Docker Desktop and Ollama are running. Verify you have pulled the required models (ollama pull qwen3.8:27b). If it still fails, reset the backend manually in a terminal with docker compose down followed by docker compose up --build -d.

9. Can I use this commercially?

StarkLLM is a Research Beta. You can use it freely, but there are no commercial warranties, support SLAs, or liability accepted for business disruption or data loss.

We welcome feedback! Email us at info@starkllm.com or open an issue on our GitHub repository.
